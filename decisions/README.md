# decisions/

Context entry point for decision-support agents (like **Compass**). Just
like Radar in `signals/`, Compass only has read tools (`Read`, `Grep`,
`Glob`) — it doesn't fetch context on its own, so the material needs to be
in text files inside the repository before requesting an analysis.

## Suggested structure

```
decisions/
  briefs/         # Decision Briefs already produced by Compass (history)
  context/        # objectives, OKRs, constraints, deadlines, budget per decision
  options/        # notes on the options/alternatives being evaluated
```

No subfolder is mandatory. What matters is that, for each decision you
want to bring to Compass, there are files describing:

- **the decision itself** (what needs to be decided, by when);
- **the desired outcome** (what result this decision should produce);
- **constraints** (budget, deadline, engineering capacity, commitments
  already made);
- **available evidence** — including, when it exists, a **Product Signal
  Brief** generated by [Radar](../signals/README.md) in `signals/briefs/`,
  which serves as direct evidence input for Compass.

## Sensitive data

The same care as `signals/` applies here: if files contain sensitive
strategic information (budget figures, unannounced roadmap), consider
keeping them out of version control via `.gitignore` and treat this
directory as a local workspace.
